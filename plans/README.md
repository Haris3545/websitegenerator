## Recommended execution order

1. **001** first — it's the token foundation nearly every other plan's CSS references (`var(--ease-out)`). Land it before anything else.
2. **002, 003** — small, isolated, highest-severity CSS-only fixes. Safe to do immediately after 001, in either order.
3. **005, 007** — the remaining executed HIGH-severity items. Independent of each other and of 002/003.
4. **008, 009, 010, 012, 013** (MEDIUM) — all independent of each other. 008 and 009 are the most mechanical (bulk className edits); do those first for quick wins.
5. **014, 016** (LOW) — mechanical/polish, independent of everything else.
6. **017–020** (missed opportunities, additive) — do last, after the corrective work has landed. 017–019 no longer depend on plan 015 (dropped) — each uses a local fallback keyframe instead.

## Notes for whoever executes these

- Every plan was written against commit `46a1b7b` — if the codebase has moved on significantly by execution time, expect some plans' cited line numbers to have drifted; each plan's own Boundaries section says to stop and report rather than improvise past that.
- Plans 008 and 014 are the largest in file-count (12 and 24 files respectively) but each is a single, repeated, mechanical edit — good candidates for a less capable/cheaper executor model.
- Plans 004, 005, 006, and 010 involve real behavioral logic changes (not just CSS/className edits) and deserve a more careful executor and reviewer.
- No plan here adds a new dependency (no motion library) — everything stays consistent with this repo's existing hand-rolled-CSS-and-Pointer-Events approach.
